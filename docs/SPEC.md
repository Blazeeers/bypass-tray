# Полное описание функционала (SPEC)

Документ для агента-исполнителя: что именно должно получиться, как это
проверять и что доделать.

## 1. Контекст и цель

На Windows-ПК используются три механизма обхода блокировок, и нет единого места,
где видно их состояние:

| Компонент | Роль | Поведение |
|---|---|---|
| **Happ** (Xray, GUI) | VPN | включён **не всегда**. Через VPN должны идти только заблокированные в РФ сервисы и западные соцсети. YouTube и Discord — **напрямую** (их закрывает zapret), а не через VPN |
| **zapret** (`Flowseal/zapret-discord-youtube`, `winws.exe`) | обход DPI | стратегия `general (ALT).bat`; закрывает YouTube и Discord напрямую |
| **tg-ws-proxy** (`Flowseal/tg-ws-proxy`) | MTProto-прокси | работает **всегда**, ускоряет Telegram Desktop |

Цель: **трей-приложение**, которое (а) агрегирует статусы всех трёх, (б) даёт
управлять ими (запуск/остановка/выбор стратегии), (в) оповещает об обновлениях
компонентов. Аналог Linux-виджета «Обходы» из `VPN-TGWSProxy-Zapret-orchestrate`,
но с Windows-бэкендом.

## 2. Что должно быть на выходе (функционал)

### 2.1 Иконка в трее

Иконка меняется по состоянию (приоритет сверху вниз):

| Приоритет | Условие | Иконка (пример) | Подсказка |
|---|---|---|---|
| 1 | Happ не запущен | красная «H»/разрыв | «Happ не запущен» |
| 2 | `winws.exe` не запущен | янтарная «Z» | «zapret (winws) не запущен» |
| 3 | tg-ws-proxy не слушает порт | янтарная «T» | «tg-ws-proxy не слушает :1443» |
| 4 | есть обновления | янтарная «U» | «Обновления: …» |
| 5 | всё в порядке | зелёная «OK» | «всё в порядке» |

Иконки можно рисовать кодом (Pillow), отдельные PNG не обязательны.

### 2.2 Панель (по клику/«Открыть панель»)

Окно со списком строк:

- **Happ** — запущен/выключен (процесс `Happ.exe`);
- **zapret** — запущен/выключен + краткий дайджест стратегии (например,
  `multisplit multidisorder`, из `--dpi-desync=…` командной строки `winws.exe`);
- **tg-ws-proxy** — слушает/не слушает порт (по умолчанию 1443);
- **Обновления** — доступные версии либо «нет».

Кнопки:

- **Zapret: запустить** — запускает выбранный `.bat` (по умолчанию
  `general (ALT).bat`), предварительно убив старый `winws.exe`;
- **Zapret: остановить** — убивает `winws.exe`;
- **Стратегия** — выпадающий список `general*.bat` из папки zapret + «Применить»
  (запоминается в конфиге; можно сразу запускать);
- **tg-ws-proxy** — запускает `TgWsProxy_windows.exe`, если не запущен;
- **Happ** — открывает Happ;
- **Проверить обновления** — разовый запрос к GitHub.

### 2.3 Меню трея

Дублирует панель быстрыми пунктами: статусы (неактивные строки), «Открыть
панель», «Zapret: запустить/остановить», подменю «Стратегия zapret» (radio),
«tg-ws-proxy: запустить», «Открыть Happ», «Проверить обновления», «Выход».

### 2.4 Обновления

- Источники: GitHub releases
  - zapret → `Flowseal/zapret-discord-youtube`;
  - tg-ws-proxy → `Flowseal/tg-ws-proxy`.
- Проверка раз в `update_check_hours` (по умолчанию 24 ч) + кнопкой вручную.
- Логика: запоминаем последний увиденный тег; если появился новый — показываем
  строку «Обновления» и **всплывающее уведомление** трея (`icon.notify`).
- Установленные версии не определяются (у инструментов нет надёжного маркера) —
  уведомляем о **новых релизах** относительно последнего просмотренного.

### 2.5 Сплит-туннель (главная незакрытая задача)

Требуется, чтобы:

- YouTube и Discord шли **напрямую** и обрабатывались zapret (`winws.exe`);
- через **Happ** шли только заблокированные в РФ сервисы и западные соцсети;
- tg-ws-proxy и Telegram Desktop — вне VPN (процесс `tg-ws-proxy`/`Telegram`).

Happ — GUI на Xray, у него есть правила маршрутизации. Нужно:

1. Составить и проверить правила Happ: `direct` для YouTube/Discord (и
   российских сервисов), `proxy` для остального/западных соцсетей.
   Черновик — в [HAPP-ROUTING.md](HAPP-ROUTING.md).
2. Проверить связку: при включённом Happ YouTube/Discord всё равно идут
   напрямую под zapret, а заблокированные сервисы — через VPN.
3. Если автоматизировать Happ нельзя — приложение должно как минимум
   **напоминать/подсказывать** и показывать состояние (статус + инструкция).

## 3. Схема статусов (JSON)

Приложение не обязано отдавать наружу JSON, но для тестируемости **должно**
иметь функцию `status.collect(cfg) -> dict` вида:

```json
{
  "happ": {"running": true, "process": "Happ.exe"},
  "zapret": {"running": true, "process": "winws.exe", "digest": "multisplit multidisorder",
             "dir": "C:\\zapret-discord-youtube", "bats": ["general.bat", "general (ALT).bat"]},
  "tgwsproxy": {"running": true, "port": 1443, "listening": true}
}
```

## 4. Конфиг

`%APPDATA%\bypass-tray\config.json`:

```json
{
  "zapret_dir": "C:\\zapret-discord-youtube",
  "zapret_bat": "general (ALT).bat",
  "tgws_exe": "C:\\...\\TgWsProxy_windows.exe",
  "tgws_port": 1443,
  "happ_exe": "C:\\...\\Happ.exe",
  "refresh_seconds": 5,
  "update_check_hours": 24
}
```

Состояние (последние увиденные версии, заметки) — `%APPDATA%\bypass-tray\state.json`.

## 6а. Автоподбор стратегии zapret

- Кнопка «Подобрать лучшую стратегию» (панель) / пункт меню трея.
- Останавливает службу zapret, замеряет связь без обхода, затем по очереди
  поднимает каждую `general*.bat`, проверяет `youtube.com` и `discord.com`
  (плюс контрольный `ya.ru`), гасит `winws.exe`.
- Ставит лучшую стратегию в службу (`sc config`/`sc create`) и запускает её.
  Если ни одна не сработала — возвращает исходную команду службы.
- Контрольный адрес нужен, чтобы отличить «стратегия не работает» от
  «интернета нет»: при недоступном контроле результат помечается как
  недостоверный.
- Установка проверена: извлечённая команда совпадает с текущей командой службы
  по всем 50 токенам, то есть рабочая конфигурация воспроизводится точно.

## 7. Ограничения

- Приложение не проверяет «магию» DPI — только факт запуска процессов и порт.
- Установленные версии Happ/zapret/tg-ws-proxy не читаются (нет стабильного
  маркера) — обновления определяются по новым GitHub-релизам.
- Файл маршрутов Happ только читается: правила меняются в самом Happ.
- Управление службой zapret требует прав администратора (запрос UAC).
- UI-тексты на русском.
