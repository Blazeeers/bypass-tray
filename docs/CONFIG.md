# Конфиг и пути

## Где лежит

- Конфиг: `%APPDATA%\bypass-tray\config.json`
- Состояние: `%APPDATA%\bypass-tray\state.json`
- `%APPDATA%` обычно `C:\Users\<вы>\AppData\Roaming`.

Файлы создаются при первом запуске; пути к компонентам определяются
автоматически, но их можно вписать вручную.

## Поля config.json

| Поле | Описание | По умолчанию |
|---|---|---|
| `zapret_dir` | Папка с `general*.bat` и `bin\winws.exe` | автопоиск |
| `zapret_bat` | Какую стратегию запускать | `general (ALT).bat` |
| `tgws_exe` | Путь к `TgWsProxy_windows.exe` | автопоиск |
| `tgws_port` | Порт локального MTProto-прокси | `1443` |
| `refresh_seconds` | Период обновления статусов, с | `5` |
| `update_check_hours` | Период проверки обновлений, ч | `24` |
| `theme` | Оформление панели: `auto` (по системе), `light`, `dark` | `auto` |

### Поведение и периодические проверки

| Поле | Описание | По умолчанию |
|---|---|---|
| `quiet_icon` | Тихая иконка: не показывать авто-уведомления, а состояние «всё работает» рисовать серым | `true` |
| `guard_enabled` | Надзиратель включён: поднимает tg-ws-proxy, перепроверяет маршруты (сервер не меняет) | `true` |
| `guard_minutes` | Период прохода надзирателя, мин | `10` |
| `health_minutes` | Период проверки сервисов (`health.collect`), мин | `10` |
| `route_audit_minutes` | Период аудита маршрутов доменов, мин | `60` |
| `autoconnect` | Подключать VPN при старте виджета; синхронизируется с наличием ярлыка автозапуска | `false` |
| `blocked_list_enabled` | Подключать встроенный список заблокированных доменов Re:filter | `true` |
| `youtube_via_vpn` | Принудительно вести YouTube/Discord через VPN (если видео застревает); в настройках применяется по «Сохранить» | `false` |
| `activity_hours` | Сколько часов журнала «что виджет сделал сам» показывать в панели | `3` |

Смену сервера делает только `TrayApp.check_proxy_health`: раз в 60 с проверяет
туннель запросом на `api.telegram.org`, меняет сервер после 3 неудач подряд и
не чаще раза в 10 минут (кулдаун после успеха и после провала смены).
`guard` сервер не трогает, чтобы не было второго владельца перезапуска Xray.

### Собственный клиент Xray

| Поле | Описание | По умолчанию |
|---|---|---|
| `xray_subscription` | Ссылка на подписку; отдаёт серверы `vless://` | ваша ссылка |
| `xray_exe` | **Зарезервировано** (в UI не настраивается); пусто = `bin\xray.exe` рядом с приложением | авто |
| `xray_port` | Локальный порт прокси (SOCKS и HTTP на одном порту) | `10818` |
| `xray_system_proxy` | Прописывать прокси в систему, чтобы им пользовались браузеры | `true` |
| `xray_routes` | Пользовательские маршруты сайтов: `{"домен": "direct"\|"proxy"}` | `{}` (создаётся миграцией) |
| `xray_stream_fallback` | Уводить YouTube/Discord в прокси, когда zapret не работает | `true` |
| `xray_extra_domains` | **Устарело.** Дополнительные домены через прокси; переносится в `xray_routes` | `[]` |
| `xray_direct_domains` | **Устарело.** Домены мимо прокси; переносится в `xray_routes` | `[]` |

### Пользовательские маршруты (`xray_routes`)

```json
"xray_routes": {
  "x.com": "direct",
  "instagram.com": "proxy",
  "geosite:youtube": "proxy"
}
```

- Домены нормализуются: схема, путь, query, порт, ведущий `*.` и `www.`
  снимаются; служебные префиксы `geosite:`, `domain:`, `full:`, `regexp:`,
  `keyword:`, `geoip:` сохраняются. Префиксы приводятся к нижнему регистру
  (у `regexp:`/`ext:` шаблон после двоеточия не меняется).
- Кириллические домены (`яндекс.рф`) принимаются и переводятся в punycode
  (`xn--d1acpjx3f.xn--p1ai`); при невозможности преобразования правило
  отклоняется с понятной причиной.
- Приоритет в правилах Xray: пользовательские `direct` → пользовательские
  `proxy` → audit direct → YouTube/Discord напрямую → встроенный список
  заблокированных → РФ/private → встроенные списки прокси и резервный режим.
  Своё правило важнее автоподбора и встроенных списков. `direct` вычитается
  из всех списков прокси, `proxy` — из списков прямых маршрутов.
- Аудит маршрутов не перезаписывает домен, у которого есть своё правило;
  старый оверрайд для такого домена удаляется.
- Миграция: если в конфиге ещё нет `xray_routes`, он собирается один раз из
  `xray_direct_domains` (direct) и `xray_extra_domains` (proxy), после чего
  оба старых списка очищаются. Если `xray_routes` уже есть (даже пустой),
  старые ключи игнорируются и при сборке конфига Xray — удалённые правила не
  воскресают. Подписка и прочие ключи не затрагиваются.

Маршрут по умолчанию — **напрямую**: через сервер идёт только явно
перечисленное. YouTube и Discord в прокси не входят — их закрывает zapret;
в сервер они уходят только при остановленном zapret (резервный режим,
`xray_stream_fallback`). Российские сервисы (`geosite:category-ru`,
`geoip:ru`) всегда идут напрямую.

### Выбор сервера и автопереподключение

Список серверов (`xray-servers.json`) собирается из подписки: каждый сервер
проверяется на доступность, недоступные отбрасываются, оставшиеся
сортируются по задержке. В панели список раскрывается строкой «Регионы и
серверы»: `★` — лучший по задержке, `●` — текущий, справа задержка.
Кнопки «Подобрать лучший» и «Обновить список» переключают сервер и
перекачивают подписку.

Туннель проверяется **по-настоящему**: `xray.verify()` делает HTTPS-запрос к
заблокированному сайту через `127.0.0.1:<port>`. Такая проверка входит в
`health.collect` (раз в `health_minutes`), а фоновый цикл раз в ~30 секунд
смотрит туннель отдельно; две неудачи подряд — сервер считается упавшим, и
Xray перезапускается на следующем по скорости живом сервере. Надзиратель
(`guard`) делает то же по результату health-проверки, но не чаще, чем раз в
`guard_minutes`.

Ядро Xray (`xray.exe`, `geoip.dat`, `geosite.dat`) лежит в `<проект>\bin`. Если
файлов нет, они скачиваются из официального релиза Xray-core
(`Xray-windows-64.zip`) — сторонние клиенты не нужны. Прокси слушает только
`127.0.0.1` и не требует прав администратора.

Пример пользовательских маршрутов (то же, что раздел «Маршруты сайтов»):

```json
"xray_routes": {
  "example.com": "direct",
  "geosite:netflix": "proxy"
}
```

Поддерживаются префиксы `domain:` (имя и поддомены) и `geosite:` (наборы
Loyalsoldier из `geosite.dat` рядом с ядром).

Исключения системного прокси (`ProxyOverride`): когда YouTube/Discord идут
напрямую (резервный режим выключен), их конкретные домены из `STREAM_DOMAINS`
добавляются туда как `домен` и `*.домен` — браузер соединяется без Xray. Если
в `xray_routes` отправлен в VPN любой домен группы YouTube или Discord, из
обхода убирается вся группа (иначе часть трафика пойдёт напрямую). При
включённом резервном режиме или `youtube_via_vpn` эти домены в обход не
добавляются.

## Встроенный список заблокированных сайтов

- Файл поставки: `data/geosite-refilter.dat` (категория `REFILTER`,
  ≈81 тыс. доменов (81 395 записей в файле), набор от 19.10.2026, MIT — `data/LICENSE-refilter.txt`);
- при первом запуске копируется в `bin` рядом с ядром
  (`blocked.ensure()`, без сети), в конфиг добавляется правило
  `{"outboundTag": "proxy", "domain": ["ext:geosite-refilter.dat:REFILTER"]}`;
- включается ключом `blocked_list_enabled` (по умолчанию `true`); если файла
  нет, Xray стартует без этого правила, а `ensure(auto_download=True)`
  пробует скачать список при подключении (не чаще раза в час);
- обновление — кнопка в настройках: файл скачивается в `*.part`, проверяется
  разбором GeoSiteList (категория `REFILTER`, число доменов) и
  `xray.exe -test`, затем атомарно заменяет старый; состояние (включая
  `last_attempt`) пишется в `blocked-list.json`;
- YouTube/Discord, свои правила и audit direct стоят выше списка; в
  исключения системного прокси список не попадает.

## Автопоиск zapret

Проверяются каталоги (по порядку):

1. `%USERPROFILE%\zapret-discord-youtube`
2. `C:\zapret-discord-youtube`
3. `%USERPROFILE%\Desktop\zapret-discord-youtube`
4. `%USERPROFILE%\Downloads\zapret-discord-youtube`
5. `<диск>:\zapret-discord-youtube`, `<диск>:\Zapret`, `<диск>:\zapret`
6. Ограниченный по глубине (2 уровня) поиск по всем дискам — признак папки:
   есть `bin\winws.exe` или `general*.bat`. Это находит вложенные раскладки
   вроде `G:\Перенос с ПК\Zapret`.

Если ваша папка в другом месте — укажите путь в `config.json` вручную.

> **Важно.** Если на машине несколько копий zapret, автопоиск выбирает первую
> найденную по порядку выше, а не обязательно ту, под которую установлена
> служба `zapret`. Сверяйтесь с записью `zapret_dir` в `config.json` и при
> необходимости поправьте её вручную.

## Автопоиск tg-ws-proxy

Имена: `TgWsProxy_windows.exe`, `TgWsProxy.exe`, `tg-ws-proxy.exe`.
Каталоги: `Downloads`, `Desktop`, `%LOCALAPPDATA%\Programs\tg-ws-proxy`,
`%USERPROFILE%\tg-ws-proxy`, затем `<диск>:\tg-ws-proxy` и
`<диск>:\TgWsProxy`.

## Ядро Xray

По умолчанию `<проект>\bin\xray.exe` вместе с `geoip.dat` и `geosite.dat`.
Поле `xray_exe` зарезервировано (в интерфейсе не настраивается). Если файлов нет, `ensure_core()` скачивает
официальный `Xray-windows-64.zip` с GitHub и раскладывает ядро в `bin`.

## Служебные файлы

Все файлы лежат в `%APPDATA%\bypass-tray` и пишутся **атомарно**: сначала
временный файл в той же папке, затем `os.replace`. При занятом файле — до трёх
попыток, после чего запись тихо пропускается. Читатель никогда не видит
половину JSON, а одновременная запись двух экземпляров не портит файл
(побеждает последняя запись).

| Файл | Назначение |
|---|---|
| `activity.json` | Журнал «что виджет сделал сам»: список `{"at", "text", "kind"}`, хранятся последние 60 записей |
| `health.json` | Кэш последней проверки: `{"checked", "items", "verdict"}`; пункты — zapret, youtube, discord, deepseek, telegram, tgwsproxy, vpn |
| `route_overrides.json` | Решения аудита маршрутов: `{"at": <время>, "routes": {"домен": {"route": "direct\|proxy\|broken", "since": <время>, "checked": <время>}}}`. Старый плоский формат (`{домен: запись}`) тоже читается. Домены из `xray_routes` сюда не пишутся — своё правило сильнее |
| `networks.json` | Стратегия zapret по сетям: `{"networks": {"<ключ>": {"bat", "at", "ssid", "gateway"}}}`. Ключ — MAC шлюза, иначе адрес шлюза, иначе SSID, иначе `default` |
| `blocked-list.json` | Состояние встроенного списка Re:filter: `{"at", "size", "source", "category"}` |
| `xray.log` | Вывод ядра Xray (`stdout`/`stderr`, дописывается); при ошибке запуска хвост ~4 КБ попадает в сообщение |
| `xray-config.json` | Текущий конфиг ядра |
| `xray-servers.json` | Проверенный список серверов |
| `xray-state.json` | Сервер, порт и режим последнего запуска |

При ошибке разбора конфиг **не перезаписывается**: файл переименовывается в
`config.json.bak-<ГГГГММДД-ЧЧММСС>`, а приложение продолжает работу с
умолчаниями. То же для `state.json`. При обычном чтении файл тоже не
перезаписывается: запись происходит только при первом запуске, миграции
`xray_routes` или когда автопоиск нашёл новые пути компонентов.

### Особенности zapret на этой машине

Zapret установлен **службой Windows** (`sc create zapret ... winws.exe`), поэтому:

- `winws.exe` запущен от `services.exe`, а не от пользовательской консоли;
- командная строка процесса `winws.exe` обычному пользователю не видна, но
  приложение берёт аргументы из реестра
  (`HKLM\SYSTEM\CurrentControlSet\Services\zapret` → `ImagePath`) — это
  доступно без прав администратора. Поэтому и дайджест стратегии, и её
  сопоставление с `general*.bat` работают (сейчас определяется
  `general (ALT).bat`);
- **запуск и остановка** выполняются через службу: `sc stop zapret` /
  `sc start zapret`. Без прав администратора приложение поднимает запрос UAC;
- **смена стратегии** службы делается в самом zapret: `service.bat` → пункт 1
  (переустановка службы) → выбор `.bat`. Приложение открывает `service.bat`
  от администратора по кнопке «Сменить стратегию службы» в меню трея;
- кнопки прямого запуска `.bat` в панели относятся к портативной установке
  (когда службы нет) и для этого случая не показываются.

Вторая, неактивная копия лежит в `G:\Перенос с ПК\Zapret` (перенос с другого
ПК). Автопоиск её игнорирует, так как `C:\Program Files\Zapret` находится
раньше по списку.
